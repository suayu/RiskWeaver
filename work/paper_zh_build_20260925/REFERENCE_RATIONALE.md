## 静态道路风险相关文献缺口

检索已经确认 DriveFuzz 能变异地图、参与者与环境要素，Crash2Scenario 能从事故记录生成包含施工区异常的场景。因此，RiskWeaver 的创新点不能写成“首次生成静态障碍物”或“此前没有施工区生成”。当前可辩护的差异是：以完整历史自车画像驱动离散风险源选择，把动态攻击轨迹和参数化施工障碍纳入同一闭环，并通过语义、几何、背景 OBB 安全和理论可行驶区域联合门控。最终定稿前仍需系统检索：

1. 自动驾驶仿真中的静态障碍物、道路施工区和车道封闭生成；
2. LLM 驱动的场景配置、地图编辑或静态道路风险生成；
3. 动态交通攻击与静态障碍物联合生成；
4. 面向规划器测试的障碍物放置、可行驶区域压缩和道路封闭基准。

只有在检索范围、关键词、数据库和检索日期均可复核后，才能使用“相关工作较少”等数量性判断；当前不使用“首个”或“首次”。

## 维护规则

- 新文献先加入本清单并写明引用理由，再加入 `references.bib`。
- 任何带“待核验”的条目不得进入最终提交版本。
- 不为增加引用数量而加入正文未使用、与贡献无直接关系的文献。
- 最终检查 BibTeX 作者、标题大小写、venue、年份、页码、DOI/URL 和正文引用是否一致。

## 2026-09-22 新增锚点扩散参考

- **Jiang et al., AnchorDrive (2026)**：与 RiskWeaver 最接近的分层危险场景生成工作。需要引用来界定共同点（LLM 语义规划、稀疏时空锚点、clean-trajectory diffusion guidance）以及差异（其第一阶段由 LLM 输出逐帧控制；RiskWeaver 保持 LLM 离散决策与 diffusion 连续细化的职责分离，并加入完整历史画像和能力评估）。
- **Chai et al., AnchDrive (2025)**：支持混合动态/静态锚点、残差预测和截断 diffusion 的技术动机。需要引用来解释未来如何从纯噪声 guidance 升级为锚点热启动，但不能把其单自车规划结果直接当作多智能体场景生成证据。
