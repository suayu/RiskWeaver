# 动态攻击排序

读取[共享契约](../shared/contract.md)，按场景分析选择[配方](../shared/recipes.md)。

先确认候选属于当前请求。比较交互机会、估计风险、背景安全裕度、可行性证据、画像匹配和不确定性，输出运行器schema要求的候选ID排序与具体理由。

只引用已列ID；目标、策略、锚点和有效期由代码从目录编译。不要重新复制/修改浮点锚点，不返回密集轨迹或动作序列。

没有画像不等于没有可执行候选，不能以历史不足为由自动放弃全部有效目录。也不能只因候选已通过初筛就声称它会通过diffusion和执行门禁。

空目录报告分层原因；目录有矛盾则指出证据，由代码处理后备候选。不绕过背景安全约束，不自行恢复关闭的道路/TTC/规避见证门控。
