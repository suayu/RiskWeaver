# 原机制与Skills的可选共同静态评估层

独立评估代码，默认关闭；没有改动公共默认入口或已冻结实验。不是Codex工具技能，不安装依赖，不发额外API、不运行仿真。

`plan_once(planner, env, state, instruction, skills_engine=None|已有引擎, builder=共同CandidateBuilder, enabled=False|True)`可在后续高层比较中使用。关闭时原样传递指令，只调用一次原机制或引擎，不加载新规则、不改变验证器。开启时，两侧都得到同一固定几何规则，使用相同路线后备OBB15米口径，并共同执行原模板/整组/背景CV/正几何面积的最终静态复核。

旧自由LLM仍自由生成原schema，Skills仍选择自身目录；评估器没有替旧模型补锚点、构造候选或重排响应。静态半组不会被记成完整成功；有效动态部分不因静态拒绝连带丢弃。原函数返回和评估副本分开保存。关闭开关保留旧语义，不能把开启共同门控称作旧默认行为完全未变。

这里统一的是静态几何和最终静态有效性；动态候选、知识、提示结构、修复次数及token上限还要在具体对照协议控制。它不是整轮公平性或可复现性的自动认证。当前仅组件/接线测试，没有新模型比较或多数覆盖结论。

不要与`skills_static_physical15_20261102.runtime.install(True)`叠加：后者在Skills内部安装相同适配器，会触发AST守卫拒绝。后续比较应选共同scope这一条装配路径，并冻结整个依赖链、固定同一模型和预算，先小规模验收实际SDK指令，再继续原A—E。
